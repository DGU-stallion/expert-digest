## 一、项目概述

### 1.1 项目背景
本项目旨在解决一个核心问题：如何让 AI 真正"学会"一个领域专家的知识体系和思考方式？

通过开发 Expert Digest 系统，我们实现了从知乎等平台爬取专家公开文章，经过结构化处理后，利用 LangGraph 编排的知识蒸馏管线，生成可供 AI Agent 直接使用的 Handbook 和技能描述文件。

### 1.2 关联项目
- **Zhihu Crawler** (`D:\Project\Zhihu_Crawler`): 知乎博主内容爬虫，基于浏览器上下文的安全爬取方案
- **Expert Digest** (`D:\Project\Expert_Digest`): 专家知识蒸馏引擎，核心业务系统

### 第二部分：数据来源与获取（3页）

#### P04 — 数据来源：知乎爬虫项目
- **项目名称**: Zhihu Crawler v0.1.0
- **技术栈**: Node.js + 浏览器上下文 (opencli)
- **核心挑战**: 知乎反爬机制，裸请求返回 403/401
- **创新方案**: 
  - 利用已登录浏览器上下文执行 fetch
  - 复用 Chrome 登录态，无需手工导出 Cookie
  - 避免复现知乎签名和风控细节

#### P05 — 爬虫技术架构与实现
- **模块拆解**:
  - `fetcher`: 分页抓取、速率限制、风控检测
  - `normalizer`: 统一内容 schema 转换
  - `transform`: HTML → Markdown/Text，图片提取
  - `writer`: JSONL 原子写入
  - `checkpoint`: 断点续爬、去重机制
- **反爬策略**:
  - 低速率 + 随机抖动 (默认 2.5s ± 抖动)
  - 保守失败策略：遇 401/403/429 立即停止
  - 最小接口集，只抓公开可见内容

#### P06 — 数据输出格式与质量
- **双层输出设计**:
  - **Raw 层**: 原始 API 响应，可追溯、可审计
  - **Normalized 层**: 标准化内容，知识库就绪
- **字段完整性**:
  - `source_type` / `source_id` — 唯一标识
  - `author_name` / `author_token` — 作者信息
  - `content_html` / `content_markdown` / `content_text` — 三格式内容
  - `created_at` / `voteup_count` / `comment_count` — 元数据
- **本次项目数据量**: 以黄彦臻为例，抓取回答 853 篇 + 文章 7 篇

### 第三部分：数据处理与存储（3页）

#### P07 — 数据处理流水线
- **导入层**:
  - 支持 JSONL、Markdown、知乎导出三种格式
  - 统一数据清洗：去重、规范化、质量过滤
- **向量化层**:
  - **创新点**: 确定性哈希词袋 Bag-of-Words
  - **优势**: 零外部依赖、纯本地计算、可复现
  - 无需调用 OpenAI Embedding API，成本为 0
- **存储层**:
  - SQLite 单文件数据库
  - 表结构：documents、chunks、embeddings、topics、communities

#### P08 — 主题聚类与知识发现
- **社区检测算法**:
  - 基于余弦相似度的相似性矩阵
  - 社区发现（Louvain 算法）
  - 主题标签生成（LLM 驱动）
- **质量评估**:
  - 轮廓系数、模块度计算
  - 聚类稳定性验证
- **输出产物**:
  - 主题-文档映射关系
  - 概念关联图谱
  - Wiki Vault 知识库目录结构

#### P09 — Wiki Vault 知识库
- **设计理念**: 类 Obsidian 的双向链接知识体系
- **目录结构**:
  - `purpose.md` — 专家核心主张集合
  - `schema.md` — 知识图谱元数据
  - `topics/` — 各主题深度分析
  - `concepts/` — 关键概念定义与溯源
- **特性**:
  - 每个概念均关联原文出处
  - 支持双向链接追踪
  - 可直接用于 Obsidian 等笔记软件

### 第四部分：核心技术：LangGraph 知识蒸馏（4页）

#### P10 — LangGraph 编排架构总览
- **编排引擎**: LangGraph StateGraph
- **设计思想**: 图状状态机，条件分支流转
- **核心节点**:
  - 分析阶段（共享）: 内容分析、表达分析、质量评估
  - 分流节点: 根据评估结果选择子管线
  - Handbook 子图: 章节规划 → 撰写 → 评审 → 编辑
  - Skill 子图: 心智模型提取 → 表达编码 → 协议设计

#### P11 — Handbook 生成子图
- **管线流程**:
  1. 章节规划 → 生成完整目录结构
  2. 并行撰写 → 各章节独立生成（支持断点续跑）
  3. 交叉评审 → LLM 自评，不合格重写
  4. 连贯性编辑 → 全文风格统一
  5. 引用追踪 → 所有观点关联原文
- **技术亮点**:
  - 增量磁盘缓存：每章独立写入，支持中断恢复
  - 选择性重写：仅重写评审失败章节
  - 引用完整性：每个论断均可追溯到原文

#### P12 — Skill 生成子图
- **生成逻辑**:
  1. **心智模型提取**: 从原文中抽象专家的思维框架、决策启发式、价值观
  2. **表达编码**: 分析专家语气、句式、确信光谱、引用习惯
  3. **智能体协议**: 问题分类器 → 研究维度 → 回答框架
  4. **质量验证**: 一致性检查、风格对齐验证
- **Skill 文件结构**:
  - 角色扮演规则
  - 核心心智模型清单
  - 决策启发式
  - 价值观与反模式清单
  - 应答协议

#### P13 — LLM 客户端与质量控制
- **双档位设计**:
  - Fast 模式: 快速生成，适合批量处理
  - Reasoning 模式: 深度推理，适合关键节点
- **重试机制**:
  - 指数退避重试
  - 温度动态调整
  - 超时保护
- **质量门控**:
  - 内容相关性检查
  - 引用完整性校验
  - 风格一致性评分
